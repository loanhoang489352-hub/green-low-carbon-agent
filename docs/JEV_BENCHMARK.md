# Jev 效果验证协议

## 评估问题与边界

比较当前同一后端路由器在 `JEV_ROUTING_MODE=off` 与 `active` 下的需求理解质量。
off 保留原规则 + DeepSeek 分类；active 保留同样规则，加入 Jev 和原有失败回退。
评估的是整个路由策略的增量价值，不是隔离后的两个基础模型榜单。
不改变业务源码、服务配置、真实账号画像、Obsidian 或运行中服务。

本轮不调用路线供应商、不生成最终家庭节能方案，因此不能证明方案更个性化、节省更多能源或业务全流程通过。
工具调用成功与分类正确分开计算；Jev 置信度不作正确性标签。

## 先固定标签，再运行

- 新增集30条：家庭节能、绿色出行、多轮上下文、否定/取消/注入等关键场景、通用咨询各6条。
- 旧回归集18条：来自上一轮，单独汇总，不混入新增集的主要判定。
- 全部为虚构中文输入；预期 act + intent 由人工可阅读的语义定义，未根据输出调整标签。
- 新增标签为本次编写者制定，尚未经独立标注者复核；小样本结果不能代表真实用户总体。
- 每条每种模式重复2次。固定种子打乱顺序，交替先后模式。仅一个进程串行调用。
- 开始前把全部样例、判定标准、样例SHA256写入结果文件；同时记录被测代码文件SHA256。
- 每条完成即保存证据；不能覆盖已有结果。总耗时预算600秒，到预算后不启动下一对。
- 超时与回退保留在结果中，不删除“不好看”的请求；错误仅记录类型，不记录敏感异常正文。

## 预先定义的提升门槛

只有同时满足以下要求才判定本次新增集存在足够的正向证据：

1. 调用级准确率至少提升10个百分点。
2. 按独立样例配对，只有两次均正确才算稳定通过；双侧精确McNemar检验 p≤0.05。
3. critical 样例中没有从原来稳定通过变成不稳定/失败的回退。
4. active 的路由耗时P95不超过 off 的1.2倍。
5. 所有计划样例运行完整。

阈值为本项目此次评测的工程验收目标，不是通用行业标准。
重复调用不当成新增独立样本扩大统计显著性；同类模板之间仍可能相关，解释统计结果时需保守。
门槛未通过的含义是“本次未证实综合提升”，不能推导模型永远无用。
未取得两家完整账单数据，不能按调用次数声称成本降低。

## 2026-09-29 实测结论

已完成48条样例 × 2种模式 × 2次重复，共192次路由评测。结果文件：`data/jev-benchmark-20260929-v1.json`。

| 新增集指标 | 关闭Jev | 开启Jev |
| --- | --- | --- |
| 正确次数 | 52/60 | 54/60 |
| 准确率 | 86.7% | 90.0% |
| 路由中位耗时 | 741ms | 826ms |
| 路由P95耗时 | 1205ms | 1401ms |
| DeepSeek分类调用 | 44 | 0 |

新增集只有1条独立样例稳定改善、0条退步；精确配对检验p=1.0，不构成显著提升证据。
改善样例是已有出行上下文下“别走那么远，重新选一条”：原路径澄清，Jev正确识别为重新规划，两次均一致。
新增集增益3.3个百分点未达到预设10个百分点；中位耗时增加约11.5%，P95增加约16.3%。
旧回归集两种模式均32/36正确（88.9%），原有两条错误仍在。

按领域：节能、出行、关键场景均为两种模式12/12；上下文由8/12改善为10/12；通用咨询仍8/12。
全部样例两次分类均一致；没有未捕获异常。成功含规则直接处理，不能全部归功于模型。
共同问题包括通用建议分类缺口、前置问候误判，以及“路线先放一边，帮我家做个省电方案”被规则要求澄清。

本次工程提升门槛未通过：存在一个可重复的局部改善，但不能声称Jev给整个智能体带来了显著或全面提升。
下一轮应先修复共享规则/分类选项问题，再用另一个未见的新测例集复核；此集保留作固定回归，不应继续称为盲测集。
