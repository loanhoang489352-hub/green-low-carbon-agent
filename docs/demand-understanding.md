# 对话需求理解

增强聊天入口（首页流式对话使用的入口）先执行统一需求理解，再选择具体业务处理。普通、ReAct、LangGraph 配置下的家庭节能与明确出行规划使用相同分流；知识解释不交给自主工具循环启动规划。旧的直接 LangGraph 流接口和基础 CLI 聊天仍有兼容路径，不属于本次完整接入范围。

## 本轮理解内容

- domain：general / energy / travel。
- act：解释、规划、补充信息、行动报告、取消、澄清等。
- relation：新任务、继续、恢复、切换、临时插问、取消。
- tasks：复合需求中尚未处理的任务。
- question：会影响下一步的歧义问题。
- source：规则或模型。原规则 confidence 仍为兼容字段，不代表经校准的概率。

规则处理明确知识咨询、假设、取消、规划和部分行动报告；模糊表达使用已配置的 LLM，提供最近有限轮次、当前任务、待补充字段和最小画像摘要。模型只提出结构化路由，不执行工具，也不提供直接写入画像的指令。输出的枚举、字段集合与任务适用性由代码校验；失败时回退规则或澄清。

家庭画像写入仍走独立的明确表达提取与检查。未能可靠提取的修改请求会询问用户，而不宣称已经记住。自由表达覆盖和真实模型识别准确率仍需继续评测。

## 配置和状态

`UNDERSTANDING_MODE=hybrid` 为默认模式：明确规则优先，模糊输入调用模型。

`UNDERSTANDING_MODE=rules` 完全关闭需求理解阶段的模型调用。

`UNDERSTANDING_MODE=shadow` 对模糊输入记录模型分类，但继续使用规则结果；日志仅记录分类，不输出原始消息。当前影子模式不是自动质量比较或自动发布机制。

模型沿用现有提供商；无可用模型或模拟模式时回退。OpenAI SDK 兼容提供商的理解调用使用 8 秒请求超时、关闭外层重试、最多 300 输出 token。其他提供商遵循自身客户端的超时实现。

`data/dialogue_state.db` 保存按 user_id + conversation_id 隔离的任务状态、待补充字段、最近 6 条截断消息和待处理任务。状态可跨进程恢复，但客户端需要继续提供同一 conversation_id。取消清空任务和待处理队列，不删除用户长期画像。

## 验证重点

测试覆盖知识词误触发、否定与假设、过去行动、简短人数回答、临时插问、切换恢复、复合需求保留、不同用户隔离、进程重建读取、无效模型 JSON、影子模式和不同运行模式的分流一致性。测试使用可控模型替身，不等于真实提供商准确率评测。
