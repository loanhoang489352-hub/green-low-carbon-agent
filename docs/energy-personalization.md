# 家庭节能：以对话和持续画像为中心

用户在主聊天里提出家庭节能需求，不需要进入独立页面。

每次节能对话读取主画像的 `basic_info` 和 `behavior_profile.home_energy_usage`，补充已有家庭记录，最后应用本轮明确提供的信息。填写的家庭类别为“3–4 人”或“5 人以上”时，不擅自转换成精确人数；需要计算时继续询问。

用户明确补充的设备、人数、费用、舒适偏好，以及已在执行或不愿执行的措施，会写回主画像。每个更新字段保留来源和时间，图谱中的同名家庭事实节点更新而不重复累积。后续修改主画像会在下次节能对话生效。设备缺失、燃气否定、舒适偏好和措施反馈决定候选建议，不把环保兴趣推断成设备拥有或真实行动。

例如：

1. 用户填写“两口之家”，告诉智能体“家里有空调和洗衣机，不用燃气”。
2. 问“帮我规划家庭节能”，得到基于这些信息的建议，不再重复填写全部资料。
3. 回复“保持舒适优先，我已经一直满桶洗衣”，后续避免调整舒适度和重复推荐满桶洗衣。
4. 回复“我家现在三人”或修改主画像，下一次建议使用更新后的信息。

Obsidian 继续作为单向开发者观察窗口，展示同一份合并画像、字段来源、变化记录和家庭事实节点。它不是另一套用户数据源，人工改写生成的笔记不会反向修改画像。既有定时同步在服务运行时更新这些页面。

主聊天的普通模式、ReAct 和 LangGraph 入口共用节能画像处理。此次取消首页新增的独立家庭节能链接和回复中强制跳页的引导；保留旧页面供兼容使用。自然语言字段和反馈提取目前是有限规则，未识别的表达不应被当成已确认事实；估算仍受设备、参数和来源约束，不表示真实设备已被控制或产生了实测收益。
