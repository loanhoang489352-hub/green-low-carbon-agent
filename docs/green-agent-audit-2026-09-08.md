# 绿色低碳智能体代码检查（2026-09-08）

## 验收口径与范围

用户已确认：出行需要真实公交/地铁/骑行/自驾路线、时间、费用、碳排比较及地图导航；家庭节能需要根据人数、设备、习惯提供有依据的节水/节电/节气建议和估算。“diamond”指代码。

本轮检查当前工作区（包含已有未提交修改），追踪聊天身份、会话、出行工具、节能规划/存储/统计及相关页面。不代表全仓安全认证；没有调用真实地图接口、验证实际导航，也没有逐条核验外部政策。未修改业务代码。

## P1：应优先修复

### 1. 登录身份可被流式聊天请求中的 user_id 替换

位置：`src/server/routers/chat.py:309`、`:357`；另见流式接口 `:240` 和推荐接口 `:129`。

stream-trace 虽要求登录，仍直接使用 body.user_id 调用 chat_enhanced，没有采用 resolve_user_id。前端 `web/index.html:2936` 正在使用该入口。已用假 handler/假 agent 复现：current_user=audit_alice，请求 user_id=audit_bob，下游实际收到 audit_bob。可能导致读取或更新他人的画像/记忆；本轮未访问真实用户数据。

修复：所有个人接口强制使用服务端登录身份；测试 A 的 token + B 的 body 身份不能调用 B 的业务上下文。

### 2. 已有会话复用不校验所有者

位置：`src/agent/conversation_store.py:76`；调用方 `src/agent/core.py:2302`。

get_or_create 收到存在的 conversation_id 直接返回，不检查 ctx.user_id。已在内存复现：B 传入 A 的 ID，返回同一个对象，owner 仍为 A。攻击前提是知道会话 ID；ID 难猜不能替代所有权验证。聊天入口未统一执行所有权检查。

修复：存储层检查所有者，历史恢复也检查持久化所有者；匿名会话使用服务端绑定身份。

### 3. 自驾路线实际来自公交路线

位置：`src/agent/tools/extended.py:675`–`:691`。

没有在此分支请求驾驶规划：距离、折线复制第一条公交路线，时长乘 0.6，费用用距离乘 0.5。结果整体标注为高德 API 来源。用户看到的自驾地图和时间并非驾驶路线，直接违背验收目标。

修复：调用独立驾驶路线接口；路线事实与费用/碳排模型估算分字段标识，缺失信息不能标为零或确定值。

### 4. 地图查询失败返回固定虚构线路

位置：`src/agent/tools/extended.py:376`–`:396`、`:763`。

无 key 或查询失败后返回固定 5km、“4号线→6号线”“26路→698路”“西直门站”等，与实际起终点无关，仍 success=True 并参与推荐。虽然 source 写了估算，但具体站点和线路不是可用估算。模拟“骑行+地铁”还记零碳排。

修复：明确返回不可用原因和重试/补充地点入口；保留成功查到的交通方式，不生成示例线路代替真实路线。

### 5. 年度节能量被显示为月度及今日节省

位置：`knowledge_base/basic/daily_living.md:97`；`src/agent/energy/policies.py:245`；`src/agent/core.py:1460`附近；`src/agent/energy/planner.py:388`。

知识库表头明确为“节省电量/年、减碳量/年”，例如空调调高1°C 为 50kWh/年。模板直接复用这些数值，聊天却显示每月省钱；今日卡又把选中行动的全额相加当今日收益。统计按日完成重复累加也没有统一周期。

修复：每条估算具有周期、频次、基线、计算公式；年度潜力与每日执行分开，避免一次设备升级每天重复计全额。

### 6. 人数和习惯没有真正用于数值估算

位置：`src/agent/energy/planner.py:184`–`:218`。

city_pricing 仅查询并记录日志，行动由设备关键词决定，金额直接复制模板。已复现：1人/空调20°C 与8人/28°C 的行动和数值完全一致。峰谷习惯影响提醒文本，但没有影响估算。

修复：建立设备功率、使用时长/次数、现有温度及实际适用电价的计算模型；信息不足时输出带假设的范围，不能宣称完成个性化测算。

### 7. 不使用燃气的家庭仍得到燃气建议

位置：`src/agent/energy/planner.py:190`；`:337`。

baseline 无条件加入 gas_baseline，并强制每类至少两个行动。已复现：只填冰箱且燃气费为0，仍推荐 gas_stove_pot_match 和 gas_stove_flame_adjust。

修复：先判断设备/能源是否存在，以及用户是否已经执行，再筛选行动；不应为了类别齐全强行推荐不适用措施。

## P2：功能闭环和可靠性

### 8. 节能方案、今日卡和统计使用不同数据链

位置：`src/server/routers/energy.py:313`、energy_today；`src/agent/energy/household_store.py:155`附近；`src/agent/energy/tracker.py:230`。

API 方案存 households.db，而完成登记及累计查 energy_actions.db 的 energy_plans。household_store.load_plan 丢弃 actions；today 即使找到 active plan，也重新生成随机 ID 的方案而不存储。聊天生成方案也只保存画像。

影响：今日卡不是原方案、完成登记无法找到收益元数据、累计为零或与显示不一致。默认 level1 返回“待激活”，本路由注册表没有对应的激活端点；需补齐确认闭环。

修复：统一方案和行动存储，读取还原完整快照，登记必须校验用户/方案/行动关系，今日卡复用既有方案。

### 9. 完成登记相信客户端金额且不校验行动归属

位置：`src/server/routers/energy.py:energy_action_complete`；`src/agent/energy/tracker.py:mark_completion_extended`。

body 可覆盖 estimated_saving_*；不存在的 action/plan 也可进入登记，日期缺少有效范围校验。返回的 credited_* 来自请求，而累计又查数据库方案，两套口径不一致。不要把此问题描述为“任意金额已持久计入累计”：当前传入金额并未用于该累计查询。

修复：服务端从归属已验证的行动读取收益，拒绝未知行动、非有限/负数和非法日期，统一返回与落库口径。

### 10. 部分家庭信息被默认值补齐后当成真实情况

位置：`src/agent/core.py:1394`–`:1429`；`src/agent/energy/models.py:58`。

新画像默认带北京、3人、账单和整套电器。只要消息抽到任意一个线索，就能绕过“未提供信息”的反问，用其余默认值生成方案。默认值也使空 API profile 看起来资料齐全。

修复：未提供字段使用 unknown；明确哪些来自用户、哪些是假设。缺少关键设备/习惯就继续询问。

### 11. 天气使用默认城市

位置：`src/agent/tools/extended.py:399`。

地理编码已经计算 geocode_city，但天气仍调用 _fetch_weather(_DEFAULT_CITY)，外地路线可能按默认城市天气打分。

修复：使用起点实际坐标/城市；无天气时标记缺失，不按其他城市天气计算。

### 12. 来源字段存在不等于数值有依据

位置：`src/agent/energy/policies.py:260`–`:270`。

空调滤网清洗的数值引用文字却是“家用电冰箱能耗”标准，加泛称厂商建议。现有无幻觉测试主要验证引用字符串和模板一致性，并未验证来源支持该结论。此处是本地引用与行动主题不匹配，不是对外部标准内容的全面核验。

修复：引用绑定可核对的具体文档段落、数值条件和周期；缺少证据时展示定性建议，不输出确定金额。

## 验证结果

- `python -m pytest tests/test_energy_no_hallucination.py tests/test_energy_planner.py -q --disable-warnings`：65 passed，34 warnings。
- 首次测试因系统临时目录权限失败；获准在沙箱外重跑后通过。不能将第一次的环境错误当产品 bug。
- 3项内存复现：家庭人数/温度变化数值不变；无燃气家庭仍有2项燃气行动；跨用户会话复用。
- 1项路由复现：登录 A、请求身份 B，stream-trace 下游收到 B。使用假 agent，没有真实模型请求或真实用户数据访问。
- 当前 Python 3.14 环境出现 Pydantic V1 兼容性警告；未据此断言实际业务故障。
- 没有运行全量测试或联网路线端到端验证。ReAct/LangGraph 的所有分支、部署配置及其余模块仍需要后续专项覆盖。

## 推荐实施顺序与验收

1. 先统一登录身份与会话所有权，增加双用户隔离回归。
2. 出行去除固定示例降级，自驾走独立真实接口；每种方式验证路线、时间、费用含义、地图折线和导航目的地一致。碳排作为有系数依据的估算展示。
3. 节能先统一年/月/日单位，再补设备适用性、真实资料收集及人数/习惯计算。相同设备不同人数、运行时间必须有可解释差异；无燃气不输出燃气操作。
4. 统一计划/行动存储，补确认激活、登记及统计一致性；重复提交同一次行动应幂等。

结论：两个功能已有界面和主要流程，但尚不能按本次确认的标准验收。优先解决身份隔离、真实路线与节能数值可信度，再扩展功能。
