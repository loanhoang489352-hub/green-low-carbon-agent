# 家庭节能：一周行动与可信估算

## 使用流程

重启服务后，打开现有 `/energy.html` 家庭节能页面：

1. 填写家庭人数并选择实际设备。城市、账单等可暂不填写；明确是否用燃气、是否有白炽灯和滴漏。
2. 选择少折腾、省钱或保持舒适，生成适用建议。已排除的设备与习惯不强行补足类别。
3. 从保存的方案选1—3件事，开始一周行动。
4. 在今日行动中按天记录全做、部分或未做；可说明影响舒适、家人不同意、设备不支持、忘记、本来就在做。
5. 查看七天执行总结和下一周调整建议。刷新页面、服务重启后保留记录；同一日同一行动再次提交是修订，不重复加分。

聊天也支持渐进收集人数和设备，明确的“没有”“不用”和费用0值不会丢弃。聊天生成的草稿会保存，可在家庭节能页面继续生成并选择行动。ReAct 工具同样使用改进后的规划器，但本次没有把一周反馈扩展成新的聊天工具。

## 数值含义

- 只有本地知识库明确给出年度周期的四类模板保留数值，并标为年度参考，不作为家庭实测收益。
- 旧模板周期或数值依据不完整的行动仅提供定性建议；兼容字段中的0表示未计入估算，不是确认收益为0。
- 淋浴计算使用用户输入：人数 × 每次缩短分钟 × 实测流量(L/min) × 每人每周次数 × 52 ÷ 1000，得到年度水量，再乘输入水价。缺少参数就不计算；不猜测热水能耗或减碳量。
- “保持舒适”优先级排除直接改变温度和淋浴时长的行动。
- 方案总量是年度参考项目的算术合计，措施可能重叠，不承诺合计收益。
- 打卡只表示用户自报执行。接口 `measurement_status=self_reported`，`verified_savings=null`；旧完成接口也不再按模板或客户端输入发放金钱/碳排收益。

## 接口与存储

- `GET /api/energy/week`：当前/最近一期行动和总结。
- `POST /api/energy/week`：`{plan_id, action_ids:[...]}`，选1—3件自己的已保存行动。
- `POST /api/energy/week/feedback`：`{week_id, action_id, level, barrier, action_date?}`。
- 三个接口都要求登录，身份来自登录上下文。禁止跨用户、未知行动、未来日期及计划范围外日期。
- `households.db` 新增 `energy_weeks` 和 `energy_week_history`，Schema Registry 集中登记；新一期启动时归档上一期快照。
- `household_plans` 恢复完整行动与真实状态，今日卡使用已激活方案，不重新生成随机ID。
- 每周只保留一个进行中的计划，进行中重复开始不会重置进度；反馈修改会重新计算执行天数。
- 不支持/已经在做的最近一期反馈用于下一次生成时筛选，不把它永久改写成已确认家庭事实。

## 验证与边界

隔离测试覆盖设备适用性、年度单位、人数/习惯计算、异常输入、幂等反馈、跨用户与日期边界、历史归档、真实路由生成到反馈闭环。另有 Edge 无界面测试验证表单、开始行动、反馈、刷新恢复和390px宽度。

```powershell
python -m pytest tests/test_energy_weekly.py tests/test_energy_planner.py tests/test_energy_no_hallucination.py tests/test_profile_wiki.py -q
$env:RUN_BROWSER_TESTS="1"
python -m pytest tests/test_energy_weekly_ui.py -q
```

浏览器测试需要 Playwright 与 Edge。测试使用隔离数据库，不请求真实设备、外部模型或地图服务。尚未接入电表、账单OCR或天气校正；不能据此宣称实际节能或归因效果。
