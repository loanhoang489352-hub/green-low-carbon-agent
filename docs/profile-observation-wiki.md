# Obsidian 画像观察库

这是开发者专用的单向 Wiki 投影。业务数据库是唯一数据依据；已有 LLM/规则画像更新会在下一次同步时体现。导出不调用额外 LLM，也不把 Wiki 总结重新当作事实，避免反馈循环。此版本没有替换业务画像推断逻辑。

## 使用

在项目根目录运行：

```powershell
python scripts/sync_profile_wiki.py --destination "D:\Obsidian\my-wiki\绿色画像观察" --configure
```

`--configure` 在已被 Git 忽略的 `data/profile_wiki_config.json` 中启用同步。启动/重启正常 Web 服务后，APScheduler 启动时及每60秒同步一次；没有运行服务时可手动执行命令。不创建额外的桌面自动任务。

在 Obsidian 打开 `绿色画像观察/画像索引.md`，点击用户进入总览，再打开局部关系图。每个用户导出总览、出行、家庭节能、证据、变化记录、图谱及受支持的图谱节点页。链接使用完整的用户相对路径，避免不同用户同名页面串联。

## 数据含义

- 用户名替换为稳定哈希观察编号。旧字段即使叫 confirmed_interests，也标为未确认，因为历史数据未提供原始消息证据。
- 证据页记录真实数据库字段位置，不伪造对话来源。历史默认家庭参数也明确标注未核验。
- 只导出允许字段；账户信息、原始聊天、出发地、目的地、坐标、地址字段及自由文本行为节点不导出。文本做进一步脱敏，但该库仍是开发者内部个人数据，不应公开发布。
- 每次快照比较记录新增/更新/移除，最多200条；它是同步观察记录，可能合并一分钟内的多次业务变化。
- 来源用户从两套库都删除后移除其生成页，保留开发者自己的笔记。只删一套库时，另一套剩余数据仍正常显示。
- 删除/替换的旧字段值不保留在变化记录中。Obsidian Sync、备份等外部历史需要独立管理。
- Wiki 手动改动会被重新导出覆盖，不回写数据库。请把开发者笔记放在不同名称的页面。
- 导出错误写日志，不影响聊天；损坏/离线数据库不会触发旧页面清理。文件逐页原子替换，同一进程内同步串行；请勿同时运行多个导出进程。

## 边界

这一版解决画像可观察、关联浏览、变化追踪。尚不提供新的候选事实确认接口、逐条聊天来源定位、事实有效期管理或 LLM 自动写入业务画像；这些需要独立接入画像收集链路。已有出行真实性、节能计算与身份隔离问题不由观察库修复。

测试：`python -m pytest tests/test_profile_wiki.py -q`。
